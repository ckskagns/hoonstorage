# 사진 기능 도입 검토 (2026-10-27)

검토 대상
1. **디데이 위젯 사진**: 원하는 사진을 골라 위젯 크기에 맞게 편집하고, 저장하면 위젯에 그 사진이 보이게 (후이·나나가 각자 다른 사진)
2. **일정 사진첩**: 일정에 사진을 여러 장 올려 두고, 나중에 일정을 누르면 사진첩이 보이게 (두 사람이 함께 봄)

검토 기준: 기능 구현, 사진 용량 관리, 사진 공유, 기타 사진 관련 사항

| 요금제 | 지금 무료(Spark) 그대로 | **Firebase Blaze(종량제) 전환 필요**, 5GB까지 무료 |

## 1. 디데이 위젯 사진

### 기능 구현

**흐름**
1. 메뉴 또는 위젯 설정에서 **사진 고르기** → 안드로이드 기본 사진 선택 창(Photo Picker)
2. **편집 화면**: 위젯 모양 틀 안에서 손가락으로 확대·이동해 원하는 부분을 맞춤
3. **저장** → 위젯이 바로 그 사진으로 바뀜

**편집 툴**
- 앱 안에 직접 만든다 (외부 라이브러리 없이 Compose 로 확대·이동·틀 맞추기).
- 틀 비율은 **실제 놓인 위젯 크기**를 읽어서 정한다. 같은 2×2 라도 폴드 커버·펼침·S26 Ultra 에서 실제 크기가 조금씩 다르기 때문이다.
- 폴드처럼 화면에 따라 위젯 크기가 달라지는 경우: 가운데 기준으로 잘라 보여주고, 편집 화면에 "커버 화면에서는 이만큼 보여요" 안내 틀을 겹쳐 보여준다.
- 추가 옵션(선택): 밝기 조절, 디데이 글자 위치(위/아래), 글자 색(흰색/검정)

**위젯 표시**
- 사진 위에 "후이 ♥ 나나 · 103일" 같은 글자를 얹고, 글자 뒤에 살짝 어두운 그라데이션을 깔아 어떤 사진에서도 잘 읽히게 한다.
- 기존 "우리둘 디데이" 위젯에 사진 옵션을 넣거나, 새 위젯 **"우리둘 사진 디데이"** 를 따로 만든다 (권장: 새 위젯. 기존 위젯 모양을 그대로 쓰고 싶은 경우도 있으므로).
- 위젯을 여러 개 놓으면 위젯마다 다른 사진도 가능하다.
- 위젯을 길게 눌러 **"위젯 설정"** 으로 사진을 다시 바꿀 수 있게 한다 (Android 12+ 위젯 재설정 기능).

### 사진 용량 관리
- 원본(보통 3~10MB)을 그대로 쓰지 않고, 편집이 끝나면 **위젯 실제 크기에 맞춰 줄인 사진 한 장**(약 100~300KB)만 앱 전용 폴더에 저장한다.
- 위젯은 사진을 시스템(홈 화면 앱)에 넘겨 그리는데, 한 번에 넘길 수 있는 양에 제한이 있다. 크게 넘기면 위젯이 안 뜨는 문제가 알려져 있어서, 위젯 크기에 맞춰 줄여서 넘기는 방식으로 피한다.
- 사진을 바꾸면 이전 사진 파일은 지운다. 폰 저장 공간은 위젯 하나당 1장분만 쓴다.

### 사진 공유
- "각자 다른 사진" 이 목표라 **서버에 올리지 않는다**. 후이 폰에는 후이가 고른 사진, 나나 폰에는 나나가 고른 사진이 보인다.
- 사진이 폰 밖으로 나가지 않아 개인정보 걱정이 없다.

### 기타
- **권한**: 안드로이드 기본 사진 선택 창을 쓰면 "사진 및 동영상 접근" 권한을 요청할 필요가 없다 (고른 사진 한 장만 앱에 전달됨).
- **앱 삭제·재설치 시 사진이 사라진다** (폰 안에만 있으므로). 업데이트로는 사라지지 않는다.
- 잠금 화면(굿락 LockStar)에도 같은 위젯을 둘 수 있다. 잠금 화면에 개인 사진이 보이는 점은 미리 안내한다.
- 다크 모드에서도 사진은 그대로 보이고, 글자 그라데이션만 조정한다.

### 결론
**바로 개발 가능.** 서버·요금제 변경이 필요 없고 비용이 들지 않는다.

## 2. 일정 사진첩

### 기능 구현

**화면**
- 일정 카드에 📷 표시와 사진 개수 (예: "📷 12")
- 일정을 누르면 상세 화면: 위에 일정 정보, 아래에 **사진 격자(썸네일)**
- 사진을 누르면 크게 보기 (확대·좌우 넘기기), **폰 갤러리에 저장**, 삭제
- **사진 추가**: 기본 사진 선택 창에서 여러 장 한 번에 (일정당 최대 50장 정도로 제한)
- 올리는 중에는 진행 표시, 앱을 닫아도 백그라운드에서 마저 올림 (인터넷이 끊기면 다시 연결될 때 자동 재시도)
- 달력 칸에도 사진이 있는 일정에 작은 📷 표시 (선택)

**데이터 구조 (예정)**
- 사진 정보: Firestore `couples/{커플}/events/{일정}/photos/{사진}` — 누가 올렸는지, 크기, 올린 시각, 파일 위치
- 사진 파일: 저장소 `couples/{커플}/events/{일정}/{사진}.jpg` + 썸네일 `..._thumb.jpg`
- 두 사람만 읽고 쓸 수 있게 보안 규칙으로 막는다 (지금 일정과 같은 방식).

### 사진 저장소 선택지

사진은 두 사람이 함께 봐야 하므로 서버에 저장해야 한다. 현재 쓰는 Firebase 무료(Spark) 요금제는 **2026년부터 사진 파일 저장소(Cloud Storage)를 쓸 수 없다**. 이 프로젝트처럼 새로 만든 프로젝트는 종량제(Blaze)로 바꿔야 저장소를 만들 수 있다.

| 선택지 | 방법 | 장점 | 단점 | 판단 |
|---|---|---|---|---|
| **A. Firebase Storage** (권장) | 요금제를 Blaze 로 바꾸고 사진 전용 저장소 사용 | 사진 저장용으로 만들어진 정식 방법, 용량 걱정 적음, 지금 로그인·보안 규칙과 바로 연결 | 카드 등록 필요, 한도 넘으면 과금 | **권장** |
| B. Firestore 에 쪼개 저장 | 사진을 작게 줄여 데이터베이스 문서에 글자로 바꿔 저장 | 지금 무료 요금제 그대로 | 문서 하나 1MB 제한이라 화질을 많이 낮춰야 함, 전체 1GB 한도를 일정·사진이 같이 씀, 나중에 옮기기 번거로움 | 임시방편 |
| C. 구글 드라이브 | 한 사람 드라이브 폴더를 상대에게 공유 | 각자 15GB 무료 | 로그인 권한 추가 요청, 공유 설정이 복잡, 드라이브에서 실수로 지우면 앱에서도 사라짐 | 비권장 |
| D. 폰 안에만 저장 | 각자 폰에 사진 연결만 | 무료·간단 | 상대가 볼 수 없음 → 목표와 다름 | 제외 |

### 사진 용량 관리
- **올리기 전에 폰에서 줄인다**: 긴 쪽 2048px, 화질 85% → 한 장 약 300~500KB (원본 3~10MB 대비 1/10 이하). 휴대폰 화면으로 볼 때는 차이를 느끼기 어렵다.
- **썸네일**: 긴 쪽 400px, 약 30~50KB. 사진첩 격자는 썸네일만 받아서 빠르고 데이터를 적게 쓴다.
- **폰 안 보관(캐시)**: 한 번 본 사진은 폰에 저장해 두고 다시 받지 않는다 (최대 약 200MB, 넘으면 오래된 것부터 자동 정리).
- **제한**: 일정당 최대 50장, 한 장 최대 10MB 원본까지 선택 가능(올릴 때는 줄인 파일).
- **예상 사용량**: 사진 있는 일정 월 10개 × 10장 × 약 0.45MB ≈ **월 45MB, 연 0.5GB 안팎** → Blaze 무료 한도 5GB 기준 약 10년.
- 메뉴에 "사진첩 사용량: 0.5GB / 5GB" 같은 표시를 넣어 한도에 다가가는지 볼 수 있게 한다.

### 사진 공유
- 두 사람 모두 같은 사진첩을 본다. 상대가 사진을 올리면 내 화면에도 바로 나타난다 (지금 일정이 실시간으로 반영되는 것과 같은 방식).
- **보안 규칙**: 커플 멤버 두 사람만 사진을 읽고 올릴 수 있고, 이미지 파일만, 한 장 10MB 이하만 허용한다. 삭제는 올린 사람만 (또는 둘 다 허용 — 선택).
- **공유 링크 주의**: Firebase 사진 주소에는 "링크만 있으면 누구나 볼 수 있는" 방식도 있는데, 이 방식은 쓰지 않고 로그인한 두 사람만 받아 볼 수 있는 방식으로 불러온다.
- 사진은 공개 깃허브 저장소와 무관한 Firebase 저장소에만 올라간다 (코드에 사진이 포함되지 않음).

### 기타 사진 관련 사항
- **위치 정보 제거**: 휴대폰 사진에는 찍은 장소(GPS)가 들어 있다. 올릴 때 줄이는 과정에서 위치 등 부가 정보를 모두 지운다.
- **삼성 카메라 사진(HEIC)**: 갤럭시 고효율 사진 형식도 안드로이드 기본 기능으로 읽어서 JPEG 로 바꿔 올린다.
- **세로·가로 방향**: 사진의 회전 정보를 반영해 바르게 저장한다.
- **동영상**: 용량이 커서 이번 범위에서는 제외 (필요하면 별도 검토).
- **일정 삭제 시**: 그 일정의 사진도 같이 지운다. 실수 방지를 위해 "사진 12장도 함께 삭제돼요" 확인 창을 띄운다.
- **원본 보관**: 앱에 올라가는 건 줄인 사진이라, 원본은 각자 폰 갤러리에 그대로 두는 것을 안내한다.
- **백업**: 사진은 서버에 있으므로 폰을 바꾸거나 앱을 다시 설치해도 남는다.
- **요금 안전장치 (Blaze 전환 시 필수)**
  - Google Cloud **예산 알림** 1달러(약 1,400원) 설정 → 넘을 것 같으면 메일 알림
  - 보안 규칙으로 파일 크기·종류 제한 (엉뚱한 큰 파일이 올라가는 것 방지)
  - 사진은 폰에 저장해 두고 다시 받지 않아 내려받기 비용도 최소화
  - 무료 한도는 저장소 지역에 따라 다를 수 있어, 만들 때 콘솔에서 무료 한도 적용 지역을 확인하고 고른다 (서울 지역으로 만들어도 이 사용량이면 월 수십 원 수준).
- **"추억" 위젯 (나중에 확장 가능)**: 사진첩 사진을 하루에 한 장씩 보여주는 위젯, "1년 전 오늘" 알림 등.

### 결론
**개발 가능.** 다만 사진 저장 서버가 필요해 **Firebase 요금제를 Blaze(종량제)로 바꿔야** 한다. 카드 등록이 필요하지만 예상 사용량이 무료 한도(5GB)보다 훨씬 작아 실제 청구는 거의 0원이다. 요금제 전환은 결제 정보가 필요해서 직접 해 주셔야 한다 (Firebase 콘솔 → 요금제 업그레이드).

무료 요금제를 꼭 유지하고 싶다면 B(Firestore 에 쪼개 저장)로 화질을 낮춰 시작할 수 있지만, 나중에 A 로 옮기는 수고가 생긴다.

## 진행 제안

1. **디데이 위젯 사진** 먼저 개발 (무료, 1~2일) → 폴드8 → S26 Ultra 환경 테스트 → 0.5.0 배포
2. 요금제 결정
   - Blaze 전환 + 예산 알림 설정 (직접) → **일정 사진첩** 개발 (4~6일) → 0.6.0
   - 또는 무료 유지 → B 방식으로 축소 개발
