# 커플앱 개발 검토안

> 작성일: 2026-10-26 · 대상 기기: Galaxy S26 Ultra (여자친구), Galaxy Z Fold8 (남자친구)
> 가칭: **"우리둘"** (코드명 `couple-app`)

---

## 1. 요약 (결론 먼저)

| 항목 | 권장안 |
|---|---|
| 앱 형태 | **안드로이드 네이티브 앱** (Kotlin + Jetpack Compose) |
| URL의 역할 | 접속 주소가 아니라 **1회용 초대 링크** (상대가 링크를 열면 두 사람이 한 공간으로 연결되고, 그 뒤로는 링크가 무효화됨) |
| 서버 | **Firebase** (로그인, 실시간 DB, 푸시 알림, 서버 함수). 2명 사용량이면 사실상 무료 |
| 위젯 | **Jetpack Glance** 홈 화면 위젯 (크기 자동 대응) |
| 배포 | Play 스토어 공개 출시 없이 **Firebase App Distribution** 또는 Play 내부 테스트로 두 폰에만 설치 |
| 화면 대응 | 화면 폭 기준 반응형 레이아웃 (폰 1단 / 폴드 펼침 2단) |

**웹앱(PWA)이 아닌 네이티브 앱을 권장하는 이유:** 안드로이드에서는 웹앱이 **홈 화면 위젯을 만들 수 없습니다.** 디데이 위젯이 핵심 기능이므로 네이티브가 필수입니다. 또한 두 사람 모두 갤럭시(안드로이드)라 iOS 대응이 필요 없어서 크로스플랫폼(Flutter 등)을 쓸 이유도 적습니다.

## 2. "단둘만 접속" 구조 설계

### 2.1 연결(페어링) 흐름

```
[A: 앱 설치 → Google 로그인 → "커플 공간 만들기"]
        │  서버가 1회용 초대 토큰 발급 (24시간 만료)
        ▼
[A: 초대 링크 공유]  https://<프로젝트>.web.app/invite/<토큰>
        │  카톡 등으로 전송
        ▼
[B: 링크 클릭 → 앱 설치 화면 or 앱 바로 열림 → Google 로그인]
        │  서버 함수 joinCouple(토큰) 호출
        ▼
[서버: 토큰 유효 + 멤버 1명뿐인지 확인 → B 추가 → 토큰 삭제 → 공간 잠금]
        ▼
[이후 두 사람만 읽기/쓰기 가능. 제3자는 링크를 받아도 접근 불가]
```

### 2.2 보안 원칙

- **로그인 필수:** Google 계정 로그인(Credential Manager). 폰을 바꿔도 같은 계정으로 로그인하면 데이터 유지.
- **멤버 최대 2명:** 공간 문서에 `members: [uidA, uidB]`를 저장하고, Firestore 보안 규칙으로 **멤버 목록에 있는 사람만** 읽고 쓰도록 제한.
- **초대 토큰은 1회용:** 사용 즉시 삭제, 24시간 지나면 만료. 토큰 원문이 아닌 해시값만 저장.
- **멤버 추가는 서버에서만:** 앱이 직접 멤버 목록을 수정할 수 없게 막고, 서버 함수만 추가 가능.

```js
// Firestore 보안 규칙 (요지)
match /couples/{coupleId} {
  allow read: if request.auth.uid in resource.data.members;
  allow update: if request.auth.uid in resource.data.members
                && request.resource.data.members == resource.data.members; // 멤버 변경 금지
  match /{sub=**} {
    allow read, write: if request.auth.uid in
      get(/databases/$(database)/documents/couples/$(coupleId)).data.members;
  }
}
```

### 2.3 초대 링크가 앱을 바로 여는 방법

- **Android App Links** 사용: `https://<프로젝트>.web.app/invite/...` 주소를 앱이 직접 열도록 등록 (Firebase Hosting에 `assetlinks.json` 배치).
- 앱이 설치되지 않은 경우: 같은 주소의 웹페이지가 "앱 설치하기" 안내를 보여줌.

## 3. 기능별 설계

### 3.1 디데이

- **한국식 계산:** 사귄 첫날을 **1일**로 셈 (`D+N = 오늘 - 시작일 + 1`). 설정에서 0일 시작 옵션도 제공.
- 자동 생성 기념일: 100일 단위(100·200·300일…), 1주년·2주년…
- 사용자 기념일: 생일, 첫 만남 등 개별 등록. **음력 날짜 지원** (생일을 음력으로 쇠는 경우 대비, 매년 양력으로 자동 변환).
- 메인 화면: 큰 숫자 "D+523" + 커플 사진 배경 + 다음 기념일까지 남은 날.

### 3.2 공유 캘린더

- 앱 안의 공유 캘린더 (Firestore 실시간 동기화). 한 명이 일정을 넣으면 상대 화면에 바로 반영.
- 일정 속성: 제목, 날짜/시간, 종일 여부, 반복, 색상, 작성자(누가 넣었는지 표시), 메모.
- 상대가 일정을 추가/수정하면 **푸시 알림** ("○○님이 '토요일 저녁 약속'을 추가했어요").
- 오프라인에서도 보기·입력 가능 (Firestore 오프라인 캐시, 연결되면 자동 동기화).
- **2단계(선택):** 삼성 캘린더/Google 캘린더로 내보내기 (안드로이드 CalendarContract 사용). 처음부터 양방향 동기화는 복잡도가 크므로 MVP에서 제외 권장.

### 3.3 기념일 알림

- **알림은 각 폰에서 직접 예약** (AlarmManager 정확 알람). 서버 푸시에 의존하지 않아 인터넷이 끊겨도 정시에 울림.
- 알림 시점 선택: 7일 전 / 3일 전 / 1일 전 / 당일 오전 9시 등 (기념일별 설정).
- 폰 재부팅 시 알림 재등록, 기념일 수정 시 즉시 재예약.
- 필요한 권한: 알림 권한(Android 13+), 정확한 알람 권한, 부팅 완료 수신.

> ⚠️ **갤럭시 배터리 관리 주의:** One UI는 안 쓰는 앱을 "절전 앱/잠자는 앱"으로 넣어 알림을 막을 수 있습니다. 첫 실행 시 **"사용하지 않는 앱에서 제외"** 설정 안내 화면을 넣어야 합니다. (설정 → 배터리 → 백그라운드 사용 제한 → 절전 예외 앱)

### 3.4 디데이 위젯

| 위젯 | 기본 크기 | 내용 |
|---|---|---|
| 디데이 | 2×2 | D+일수, 커플 사진 배경 |
| 디데이 가로 | 4×1 | D+일수 · 다음 기념일까지 D-N |
| 일정 | 4×2 | D+일수 + 다가오는 일정 3개 |

- **Jetpack Glance**의 반응형 크기 모드로 칸 크기에 따라 레이아웃 자동 변경 (폴드 커버/메인 화면에서 칸 크기가 다르기 때문에 필수).
- **자정 갱신:** 안드로이드 위젯 기본 갱신 주기(최소 30분)는 날짜 변경에 정확하지 않으므로, 매일 00:00에 알람으로 위젯을 강제 갱신.
- 위젯은 네트워크가 아닌 **폰에 저장된 데이터(DataStore)**를 읽어 즉시 표시.
- 데이터 변경(시작일 수정, 일정 추가) 시에도 즉시 갱신.

### 4.1 기기 화면 사양

| | Galaxy S26 Ultra | Galaxy Z Fold8 커버 | Galaxy Z Fold8 메인(펼침) |
|---|---|---|---|
| 크기 | 6.9" | 5.5" | 7.6" |
| 해상도 | 3120×1440 (QHD+) | 1248×1972 | 1848×2448 |
| 비율 | 약 19.5:9 (길쭉) | **10:16 (넓적)** | **4:3 (거의 태블릿)** |
| 주사율 | 1–120Hz | 1–120Hz | 1–120Hz |
| OS | One UI 8.5 (Android 16) 출시 | One UI 9 계열 | 〃 |
| 특이사항 | 프라이버시 디스플레이, S펜 | 기존 폴드보다 훨씬 넓은 커버 | 기존 폴드의 정사각형 → 가로형 4:3 |

> Fold8은 기존 폴드(커버 21:9 길쭉, 메인 정사각형)와 **화면 비율이 완전히 달라졌습니다.** 예전 폴드 기준의 고정 레이아웃은 쓰면 안 되고, 반드시 **화면 폭 기준 반응형**으로 만들어야 합니다.
> (모델이 Fold8 Ultra 등 다른 파생 모델이라면 수치는 달라지지만, 아래 반응형 설계로 그대로 대응됩니다.)

### 4.2 예상 화면 폭 구간 (Android Window Size Class)

| 화면 | 예상 폭(dp, 추정) | 구간 | 레이아웃 |
|---|---|---|---|
| S26 Ultra 세로 | 약 384–412dp | Compact | 1단: 월 캘린더 + 아래 일정 목록 |
| Fold8 커버 세로 | 약 440–480dp | Compact (넓은 편) | 1단, 여백·글자 약간 키움 |
| Fold8 메인 (세로로 잡음) | 약 700–750dp | Medium | 2단: 캘린더 \| 선택한 날 상세 |
| Fold8 메인 (가로로 잡음) | 약 950–1000dp | Expanded | 2단 + 사이드 네비게이션 레일 |
| S26 Ultra 가로 | 약 830–900dp | Medium/Expanded | 2단 |

> dp 값은 기본 화면 크기 설정 기준 추정치입니다. 실제 기기에서 `adb shell wm size` / `adb shell wm density`로 확인 후 확정하세요.

### 4.3 필수 대응 항목

1. **화면 방향·크기 고정 금지**
   Android 16부터 폭 600dp 이상 화면(=폴드 메인)에서는 앱의 세로 고정·크기 고정 설정을 시스템이 무시하고, Android 17(API 37) 타겟부터는 아예 예외가 없어집니다. → 처음부터 **모든 크기·방향에서 깨지지 않게** 설계.
2. **접기/펼치기 시 상태 유지**
   커버에서 일정 입력 중 펼쳐도 입력 내용이 사라지지 않도록 ViewModel + `rememberSaveable`로 상태 보존.
3. **Edge-to-edge (화면 끝까지 그리기)**
   Android 15+ 타겟 시 강제. 상단 카메라 구멍, 하단 제스처 바 영역을 침범하지 않게 Insets 처리.
4. **위젯 크기 반응형**
   폴드는 커버 홈과 메인 홈의 칸(셀) 크기가 다릅니다. 같은 2×2 위젯이라도 실제 픽셀이 달라지므로 Glance 반응형 크기 3종 이상 정의.
5. **글자 크기 확대 대응**
   삼성 폰은 글꼴·화면 확대 설정을 바꾸는 경우가 많음. 모든 글자는 `sp` 단위, 글꼴 크기 최대(약 200%)에서도 디데이 숫자가 잘리지 않는지 테스트.
6. **다크 모드** — One UI 다크 모드 연동, 커플 사진 위 글자는 반투명 그라데이션으로 가독성 확보.
7. **120Hz 부드러움** — 캘린더 월 넘김 스와이프가 끊기지 않게 Compose `HorizontalPager` + 지연 로딩 사용.

### 4.4 있으면 좋은 항목 (2차)

- **플렉스 모드 (반쯤 접어 세운 상태):** 위쪽 절반에 디데이·사진, 아래쪽에 이번 주 일정. (Jetpack WindowManager의 접힘 상태 감지)
- **멀티윈도우/팝업 화면:** 폴드에서 카톡과 나란히 띄워 쓰는 경우를 위해 최소 크기에서도 동작 확인.
- **접힘 선(힌지) 회피:** 반쯤 접힌 상태에서 중요한 글자가 접히는 선 위에 오지 않게 배치.

## 6. 데이터 구조

```
users/{uid}
  ├─ displayName, photoUrl
  ├─ coupleId
  └─ fcmToken

couples/{coupleId}
  ├─ members: [uidA, uidB]          // 최대 2명
  ├─ startDate: 2025-05-12          // 사귄 날
  ├─ countFromOne: true             // 1일부터 셈
  ├─ coverPhotoUrl
  ├─ inviteTokenHash, inviteExpiresAt   // 연결 완료 후 삭제
  │
  ├─ events/{eventId}               // 공유 일정
  │    title, start, end, allDay, repeat, color, memo, createdBy, updatedAt
  │
  └─ anniversaries/{annId}          // 기념일
       name, date, isLunar, repeatYearly, notifyBefore: [7, 1, 0], notifyTime: "09:00"
```

## 9. 테스트 계획

- **실기기:** S26 Ultra(세로/가로), Fold8 커버 → 펼침 → 다시 접기, 반쯤 접기.
- **에뮬레이터:** Android Studio의 "Resizable" 에뮬레이터로 여러 폭 빠르게 확인.
- **시나리오 체크리스트**
  - [ ] 초대 링크를 제3자가 다시 열면 거부되는가
  - [ ] 기념일 알림이 폰 재부팅 후에도 울리는가
  - [ ] 자정이 지나면 위젯 숫자가 바로 바뀌는가
  - [ ] 커버에서 입력 중 펼쳐도 내용이 유지되는가
  - [ ] 글꼴 최대 크기에서 디데이 숫자가 잘리지 않는가

## 11. 결정이 필요한 사항

1. **개발 방식:** 네이티브(Kotlin) 권장. 위젯을 포기하고 웹(PWA)으로 빠르게 갈지 여부.
2. **Fold 모델 확인:** Fold8 일반 모델인지, 파생 모델(Ultra 등)인지.
3. **배포 방식:** Firebase App Distribution(무료) vs Play 내부 테스트(개발자 계정 $25, 업데이트 편함).
4. **디데이 계산:** 사귄 날 = 1일(한국식) 기본값 확정.
5. **2차 기능 범위:** 삼성 캘린더 내보내기, 플렉스 모드, 사진 앨범 등.
