# 가계부 · 자산관리 설계 (2026-11-02)

결제 알림 읽기로 데이트 통장(토스뱅크 모임통장·모임카드) 결제를 자동으로 모으고, 그 데이터를 바탕으로 나중에 자산관리까지 넓힌다.
참고 앱: Google Play **모두의가계부 (M-Ideas, `com.moduideas.budget`)**. 기능 목록은 아래와 같다.
- 카드 문자·앱 알림 자동 인식, 미확인 내역 대기 목록
- 공유 가계부, 구성원별 지출
- 자산·부채 관리 (잔액·월별 추이)
- 월별·연간 통계, 카테고리 분석, 달력 보기
- 카테고리별 월 예산
- 고정·반복 거래, 할부 추적
- 휴지통(72시간), 엑셀 내보내기, 홈 위젯, 주간 보고서
- 광고 문자 걸러내기, 카테고리 자동 매칭

우리둘은 이 항목을 모두 담을 수 있는 데이터 구조로 시작한다. 1차로는 **수집·저장·확인**을 만들고, 나머지 화면은 같은 데이터 위에 하나씩 올린다.

## 1. 데이터 구조 (Firestore `couples/{coupleId}/…`, 두 사람만 읽고 쓰기)

모든 문서에 `v`(구조 버전)를 둬서 나중에 칸을 더해도 예전 앱이 깨지지 않게 한다. 금액은 **원 단위 정수**(소수 오차 없음)로 저장한다.

### `ledgerEntries/{id}`: 거래 한 건 (가계부의 중심)

| 칸 | 뜻 | 예 / 메모 |
|---|---|---|
| `v` | 구조 버전 | 1 |
| `type` | 종류 | `expense` 지출 · `income` 수입 · `transfer` 이체 |
| `amount` | 금액 (원, 0 이상) | 38000 |
| `cancel` | 결제 취소·환불이면 true (합계에서 뺌) | false |
| `date` / `at` | 날짜 "yyyy-MM-dd" / 시각(밀리초) | 달별 조회는 `date` 로 |
| `merchant` | 가맹점·내용 | "스타벅스 선릉역점" |
| `memo` | 메모 | |
| `category` | 분류 키 "대분류.소분류" | `food.cafe` (아래 표) |
| `assetId` | 결제 수단(자산) | 모임카드 |
| `toAssetId` | 이체일 때 받는 자산 | |
| `paidBy` | 쓴 사람 uid (모르면 없음) | 구성원별 지출 |
| `status` | `confirmed` 확정 · `pending` 확인 필요 | 대기 목록 |
| `source` | `notification` · `sms` · `manual` · `import` · `recurring` | |
| `sourceApp` | 알림을 보낸 앱 | `viva.republica.toss` |
| `raw` | 알림 원문 `{title, text}` | 나중에 글 풀기를 고쳐 다시 풀 수 있게 보관 |
| `parser` | 글 풀기 이름·버전 | `toss@1` |
| `balanceAfter` | 알림에 잔액이 있으면 결제 뒤 잔액 | 자산 추이 |
| `installment` | 할부 개월 (0 = 일시불) | |
| `recurringId` | 반복 거래에서 생겼으면 그 ID | |
| `eventId` / `tags` | 연결된 일정 / 태그 목록 | 데이트 하루 비용 |
| `deleted` / `deletedAt` | 휴지통 (바로 지우지 않음) | 되살리기 |
| `createdBy` · `updatedBy` · `createdAt` · `updatedAt` | 기록 | |

**중복 막기**: 알림에서 온 거래의 문서 ID 는 `n_` + (종류·금액·가맹점·3분 단위 시각)의 해시로 만든다. 두 사람 폰이 같은 결제 알림을 받아도 한 건만 남는다. 경계에 걸리는 경우를 위해 바로 앞 3분 칸도 확인한다.

### `ledgerAssets/{id}`: 자산·부채 (자산관리의 중심)

| 칸 | 뜻 |
|---|---|
| `name` | "데이트 통장", "모임카드", "현금" |
| `kind` | `bank` 통장 · `card` 카드 · `cash` 현금 · `savings` 적금 · `investment` 투자 · `loan` 대출 · `other` |
| `institution` | "토스뱅크" |
| `linkedAssetId` | 카드가 빠져나가는 통장 (모임카드 → 데이트 통장) |
| `openingBalance` / `openingDate` | 시작 잔액·날짜 (잔액 = 시작 + 이후 거래) |
| `lastBalance` / `lastBalanceAt` | 알림에서 읽은 최신 잔액 (계산값과 대조) |
| `matchers` | 알림 글에 이 말이 있으면 이 자산 ("모임카드", "모임통장") |
| `archived`, `order`, `color` | 숨김·순서·색 |

### 앞으로 붙일 것 (같은 틀 위에)

- `ledgerBalances/{assetId}_{yyyy-MM}`: 달마다 잔액 기록 → 자산 월별 추이
- `ledgerBudgets/{yyyy-MM}`: `{ total, byCategory: { "food": 300000 … } }` → 예산
- `ledgerRecurring/{id}`: 반복 거래 틀 (금액·분류·매달 며칠) → 매달 자동 등록
- `ledgerSettings/main`: 사용자 분류 추가

### 분류 (기본값, 사용자가 추가 가능)

| 대분류 | 소분류 |
|---|---|
| 식비 `food` | 식사 `meal` · 카페·간식 `cafe` · 배달 `delivery` · 술 `drink` |
| 데이트·여가 `date` | 영화·공연 `culture` · 놀거리 `play` · 여행·숙박 `travel` · 선물 `gift` |
| 교통 `transport` | 대중교통 `transit` · 택시 `taxi` · 주유·주차 `car` |
| 쇼핑 `shopping` | 생활용품 `living` · 옷·꾸미기 `fashion` · 온라인 `online` |
| 생활 `life` | 통신·구독 `subscription` · 공과금 `bill` · 병원·약국 `health` |
| 기타 `etc` | 기타 `etc` |
| 수입 `income` | 모임비 입금 `deposit` · 이자 `interest` · 환급 `refund` · 기타 `etc` |

분류는 이 순서로 자동으로 정한다 (`LedgerCategories.guess`).

1. **우리 둘 학습표** `ledgerMerchants/{정리한 가맹점 이름}` = `{ merchant, category, updatedBy, updatedAt }`
   - 거래의 분류를 고치거나, 직접 기록할 때 짐작과 다른 분류를 고르면 그 가맹점을 기억한다. 두 폰이 같은 표를 쓴다.
   - 고친 거래면 "같은 가맹점의 다른 기록 N건도 바꿀까요?"라고 묻는다 (가맹점 글자가 같은 지출만).
   - 알림으로 들어온 결제는 서버에 올릴 때 이 표를 먼저 본다.
2. **기본 사전** (앱에 들어 있음): 가맹점 이름에 정해 둔 말이 있으면 그 분류.
   결제 알림에는 영문·회사 이름(Agoda, (주)우아한형제들, NETFLIX.COM …)으로 오는 일이 많아 함께 적어 둔다.
   여러 말이 맞으면 가장 긴 말 (쿠팡플레이 > 쿠팡). 3자 이하 영문은 낱말 단위로만 (CU ≠ CURRY).
3. 그래도 없으면 `etc.etc`.

가맹점 이름 정리: 대문자, (주)·주식회사 빼기, 글자·숫자만 (띄어쓰기·점·밑줄 없음 → 문서 이름으로 써도 안전).

검토했지만 쓰지 않은 자료: 소상공인 상가(상권)정보(전국 가게 업종, 수백 MB에 같은 이름의 가게가 많아 상호명만으로는 업종이 갈림),
카카오 로컬 장소 검색(앱에 키를 넣어야 하고 결제마다 가맹점 이름이 밖으로 나감).

## 2. 자동 수집 흐름

1. **알림 받기** (`PaymentNotificationService`, 안드로이드 알림 접근)
   - 앱 안 "자동 기록"을 켜고, 폰 설정에서 알림 접근을 허용해야 동작한다.
   - **허용된 금융 앱(지금은 토스) 알림만** 읽는다. 다른 앱 알림은 열어 보지도 저장하지도 않는다.
2. **글 풀기** (`PaymentParser`)
   - 앱마다 글 풀기를 둔다(`TossPaymentParser`). 금액, 결제/취소/입금, 가맹점, 쓴 사람(○○님), 잔액을 뽑는다.
   - 광고·혜택 알림은 버린다.
   - 확실하면 `confirmed`, 애매하면 `pending`(확인 필요)으로 둔다.
3. **폰에 먼저 보관** (`PaymentInbox`): 인터넷이 없거나 앱이 꺼져 있어도 잃지 않게 폰에 먼저 쌓는다.
4. **올리기** (`LedgerUploadWorker`): 인터넷이 되면 Firestore 에 올린다(중복 막기 ID). 올린 것은 폰 보관함에서 지운다.
5. **확인**: 가계부 탭의 "확인 필요" 목록에서 분류·가맹점을 고쳐 확정하거나 지운다.

카드사 문자(SMS)나 다른 카드 앱은 `PaymentSources` 에 글 풀기 하나만 더하면 같은 흐름에 붙는다.

## 3. 화면 구성 제안 (가계부 탭, 자산관리 중심)

탭 안 위쪽에 **자산 · 내역 · 통계 · 예산** 네 칸을 두고, 오른쪽 아래에 [+ 직접 추가] 버튼을 둔다.

1. **자산 (첫 화면)**
   - 맨 위 큰 카드: 순자산(자산 − 부채)과 지난달 대비 증감, 데이트 통장 잔액.
   - 이번 달 요약: 지출 · 수입 · 남은 예산 막대.
   - 자산 목록: 통장 / 카드 / 현금 / 적금·투자 / 대출을 묶어서 각 잔액, 누르면 그 자산의 내역과 월별 추이.
   - "확인 필요 n건" 알림 띠: 누르면 대기 목록.
   - 최근 거래 5건.
2. **내역**
   - 달 넘기기, 목록 ↔ 달력 보기 전환.
   - 날짜별로 묶은 거래, 하루 합계.
   - 분류·자산·사람(후이/나나) 필터, 검색.
   - 거래를 누르면 상세·수정(분류, 메모, 일정 연결).
3. **통계**
   - 분류별 도넛, 최근 6개월 막대, 가맹점 TOP 5.
   - 데이트 1회 평균 비용(일정과 연결된 지출), 후이/나나 결제 비율.
4. **예산**
   - 이번 달 데이트 예산과 분류별 예산 진행 막대.
   - 저축 목표(예: 여행 자금) 진행률.

우리둘만의 연결: 일정 상세·일기장 게시물에 "이 날 쓴 돈"을 보여 주고, 캘린더 날짜 칸에 지출 점을 표시한다.

## 4. 단계

- **1차 (이번)**: 데이터 구조·서버 규칙, 알림 수집·글 풀기·중복 막기·폰 보관·올리기, 가계부 탭(자동 기록 켜기 안내, 확인 필요 목록, 이번 달 내역·합계, 기본 자산 2개).
- **2차**: 위 화면 구성(자산·내역·통계·예산), 직접 추가·수정, 분류 학습.
- **3차**: 반복 거래, 할부, 잔액 월별 추이, 엑셀 내보내기, 일정·일기장 연결, 위젯.

실제 토스 알림 문구를 받으면 `TossPaymentParser` 를 맞추고, 보관해 둔 원문(`raw`)으로 지난 거래도 다시 풀 수 있다.
