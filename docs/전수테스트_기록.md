# 전수테스트 기록

"전수테스트 진행해" 를 받으면 아래 순서로 진행하고, 회차마다 결과를 여기에 적는다.

1. 코드 리클러스터링 — 큰 파일 나누기, 중복 합치기, 역할별 정리 (동작은 그대로)
2. 속도·처리 효율 개선 — 불필요한 서버 읽기·반복 계산·다시 그리기 줄이기
3. 버그 확인 — 최근 바뀐 코드부터 다시 읽고 고치기 (+ lint 검사)
4. 기능 테스트 — 단위 테스트 → 에뮬레이터(S26 Ultra 환경) → 폴드8 실기기(서버 저장까지). 테스트 데이터는 "test0…" 이름으로 만들고 끝나면 지움
5. 결과 기록·커밋 (배포는 따로 요청할 때만)

## 2026-11-20 (21회차: 일정을 옮기면 사진·후기도 함께, 반복 일정 "이 날만 / 반복 전체")

계기: 사용자 "12월 2일 일정을 11월 25일로 수정하니 사진과 후기가 있으면 수정이 안 됨". 서버를 보니 "수요데이트😍"는 **매주 반복 일정**(10/28 시작)이고 12/2 날에 사진 3장·후기 1개. 반복 일정의 하루 날짜를 바꾸면 반복 전체가 옮겨지고(12/2→11/25 = 반복 전체 −7일), 사진·후기는 "일정 ID + 날짜"로 묶여 예전 날에 남는 구조였음.

| 단계 | 결과 |
|---|---|
| 고친 것 | ① 일정 날짜를 바꾸면 그 일정의 사진(날짜만 고침)·후기(새 ID 로 옮김, 두 사람 후기·고친 시각 그대로)도 함께. 반복 일정은 몇 번째 반복인지 그대로 ② 반복 일정의 하루 날짜를 바꾸면 "이 날만 옮기기 / 반복 전체 옮기기 / 취소" 를 물음. 이 날만: 그 날은 반복에서 빼고, 옮길 날이 이미 그 반복의 날이면 거기에 합침(새 일정 없음), 아니면 반복 없는 일정을 새로 만들고 사진·후기를 그 일정으로 ③ 상대 폰: 같은 달 안에서 옮기면 사진 수가 같아 저장해 둔 사진 달력을 그대로 쓰던 것 → 일정과 날짜가 어긋난 칸이 있으면 그 달을 다시 받음(달마다 5분에 한 번까지) |
| 보안 규칙 | 사진 문서는 고치기 금지였음 → `date`·`eventId` 만 고칠 수 있게 (사진·올린 사람·주는 그대로). date 만 고치는 판은 배포(사용자 확인), eventId 까지 고치는 판은 **배포 대기** |

| 버그 확인 | 다시 읽기: 물음 창을 띄운 뒤 달을 넘기면 원본을 못 찾을 수 있던 것 → 물을 때의 원본을 기억. 안내 글 띄어쓰기("사진 도"). lint 오류 0, 바뀐 파일 새 경고 0 |
| 단위 테스트 | 208개 모두 통과 (새로: MemoryMove 8개 — 반복 안 함·매주·매달(31일)·매년, 반복 방식 바꿈, 매주 12/2→11/25 합치기, 묻는 경우, 상대 폰 어긋난 달) |
| 규칙 시험 (서버에 안 씀, Rules test API) | 9개 통과: 상대가 올린 사진 날짜 고치기 허용, 날짜+일정 허용(새 규칙), 올린 사람·사진 내용·날짜 형식·커플 아닌 사람 금지, 후기 새 날짜·새 일정으로 만들기 허용, 예전 후기 지우기 허용 |
| 에뮬레이터 (S26 Ultra, 데모) | 매주 화요일 "같이 운동": 12/1→11/24 "이 날만" → 12/1 빠지고 11/24 에 합쳐짐 / 12/8→12/9 "이 날만" → 12/8 빠지고 12/9 에 새 일정 / 12/1→11/24 "반복 전체" → 시작이 11/3 으로, 화요일마다 그대로. 앱 꺼짐 0 |
